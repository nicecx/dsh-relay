## 背景与问题（2026-09-02 实战暴露）

主会话无法直接通知 Insta360 会话（"暂停上传"协调）——只能**用户转达 + 协调文件**（UPLOAD-COORDINATION.md）。多会话并行时（投资/Insta360/主会话/环境配置），跨会话协作靠人肉转达，无机制。**核心用例：向非活跃会话（如 Insta360）投递通知，其下次激活时收到**。

## 方案：会话 inbox 机制（~/.dsh/session-inbox/）

### 1. 存储：每会话一个 inbox 文件（严格 append-only）

```
~/.dsh/session-inbox/
├── <sessionId>.jsonl          # 发给该会话的消息（严格 append-only，永不移走/改写单条）
├── <sessionId>.lastRead.json  # 已读水位（独立状态文件，原子写 temp+rename）
└── PROTOCOL.md                # 协议说明
```

消息格式（**单行一条 JSON**）：
```json
{"id": "msg-<uuid>", "ts": "...", "from": "<发起会话id>", "to": "<目标会话id>",
 "kind": "notice|request|coordinate", "text": "...", "ref": "可选引用"}
```

**写约束（M6）**：同 inbox 多发送方并发 append 一律 `fs.appendFile`（O_APPEND，单行一条消息），**禁止 read-modify-write 整体改写**——并发安全靠内核 O_APPEND 原子性。

**归档（M3+N3，025 修正实现顺序）**：归档 = ① 读未投递尾部（water.offset..size）为迁移行
② rename 旧文件 → `<sessionId>.jsonl.archived-<ts>`（原子，旧内容安全）
③ 重建 `<sessionId>.jsonl`：**一律 `appendFileSync`（O_APPEND|O_CREAT，永不截断）**先落迁移行，
tail 为空同样以 append 创建空文件——跨进程窗口（rename 与重建之间并发 append 已建文件）
只追加不覆盖（025：writeFileSync('') 截断窗口已消除）
④ 水位 offset 归 0（迁移行从 0 重读投递，不丢）。
单条消息永不被删除/改写——append-only 即审计。跨进程安全以**单实例**为前提（多实例
并行运行同一 DSH 网关目录不在支持范围，与既有插件一致）。

### 2. 已读水位（M3 拍板：独立状态文件，不移动文件）

- 读后推进水位：`<sessionId>.lastRead.json` 单行 `{"lastReadId": "<msg-id>", "ts": "..."}`，**原子写（temp 文件 + rename）**
- 轮询方每次只投递 `id > lastReadId` 的消息；投递成功后推进水位
- 不用"移动 read 文件"方案——破坏 append-only 审计

### 3. 写入与投递：dsh-relay 扩展（M1 拍板：实现落点 = dsh-relay 扩展）

**落点拍板：扩展 `~/.dsh/plugins/dsh-relay/`**（复用其现有 poll 循环与 deliver 机制）——理由：免新插件生命周期与 cordis.patch insert 冲突风险（bundles 自动装载插件绝不能 insert，两次事故教训）；followup/deliver 机制已在 relay 内（复用 035 deliver 路径）。不建独立插件。

- 新工具 `session_send(to, text, kind?, ref?)` → append 到 `<to>.jsonl`
- **sender 身份（M4）**：`from` 由工具服务端取自**调用会话上下文**（ctx.agentId），**不接受客户端传参**（防伪造）

### 4. to 校验：分级校验 + 持久化注册表（N1 阻塞修正）

**校验源（N1①）**：**持久化会话注册表 = 磁盘扫描 `~/.dsh/sessions/`**——结构为 `<cwd编码目录>/<sessionId>/session.jsonl.zstd`（会话日志即存在证据，含**非活跃会话**）。实测目录形态两种：`session-<uuid>`（新命名）与裸 `<uuid>`（旧遗留），均含 `session.jsonl.zstd`。
- **禁止**用 `ctx.agents` 作唯一校验源（仅覆盖运行中会话——若照此实现，非活跃目标发送时即被拒，M2 留存路径不可达，核心用例失效）
- **禁止**全量 `session.list` RPC（restore 风暴教训）

**分级校验语义（N1②）**：
1. 格式非法（非 `session-<uuid>` 亦非裸 `<uuid>`）→ **拒绝 + 审计** `send-rejected:format`
2. 注册表未命中（磁盘扫描无该会话目录/无 session.jsonl.zstd）→ **拒绝 + 审计** `send-rejected:unknown`
3. 命中（**无论活跃与否**）→ **接受入 inbox 留存**（活跃性只影响投递时机，不影响发送）

### 5. 投递语义（M2 关键补丁：非活跃会话）

**实测基线**：relay `injectToSession` 走 `ctx.agents.get(id)`——目标会话**无运行中 agent 即投递失败**（"无法注入"）。

**投递语义定义**：
1. 目标会话**活跃**（有运行中 agent）→ 本轮 poll 直接投递（role:user 普通消息帧，见第 6 节）
2. 目标会话**非活跃** → 消息**留存 inbox 文件不丢**（水位不推进），记审计 `deliver-deferred`
3. 目标**激活时 drain**：relay 每轮 poll 对当前活跃目标检查 inbox，有新消息即补投（水位推进）
4. 投递失败（注入报错）→ 记审计 `deliver-fail`，**禁止无限重试**（下轮 poll 自然再试，不设重试循环）

### 6. 投递帧形态（M4）

- 投递 = **role:user 普通消息帧**（沿用 relay GUARDRAIL_PREFIX 路径即可），**禁止以 system/instruction 帧注入**——这是"防跨会话指令注入"的实际落点
- 收方 agent 收到的是普通用户消息（带来源标注），自行判断是否执行——消息无命令语义

### 7. 轮询挂载与扫描成本（N2 阻塞修正；025 同步为独立 job）

**挂载（025 实际实现）**：**独立 `dsh-relay-inbox` 宿主 job**（`jobs.start({kind:'dsh-relay-inbox', ...})`，默认周期 `inboxPollSecs=5`）——不依赖 imessage/email 通道是否启用，与通道 poll 并行。投递时延上界 ≈ 5s + 处理耗时；非活跃会话的时延上界 = 其激活时刻 + 5s。**以 `~/.dsh/session-inbox/PROTOCOL.md` 为权威描述**。

**每 tick 扫描成本上界（N2②）**：每 tick 只做：
1. `readdir` + `stat` 各会话 inbox 文件（**排除 `audit.jsonl`**——025：审计文件非消息、无水位，误扫会导致每 tick 全量读 + 超限被归档改名，审计链断裂）
2. 水位后无新增（size ≤ water.offset）→ 本轮跳过（零读）
3. 有新增 → **按水位字节偏移增量读新行**（`fs.read` 从 offset 续读），**禁止全量读大文件**

**"不新增裸定时器"纪律保留（N2③，与 004 一致）**：轮询走宿主 job 机制（jobs.start），不新增 setTimeout/schedule 裸定时器。

### 8. kind=request 的回复路由（M5 明示：无自动回复路由）

- `coordinate`/`notice` 单向消息，够用
- `request` 暗示收方回应——**回复走同一机制**：收方 `session_send` 回去（`ref` 携带关联 msg id），**不存在自动回复路由**，防止实现者发明第二套机制

### 9. 与现有机制关系

- 不取代 review-handoff（审核协议）/task-queue（任务队列）——inbox 是**会话间轻量消息**（协调/通知）
- deliver 审计复用（deliver-ok/fail/deferred 记录，035）
- 004 schedule 纪律一致（无裸定时器，见第 7 节）

## 接口与兼容性

- 工具：`session_send(to, text, kind?, ref?)`（挂 dsh-relay）
- inbox 文件新路径（不影响既有协议）；目标会话无感知改动（收方由 relay 轮询投递）
- from 恒为服务端取调用会话 id；to 分级校验（格式 → 注册表 → 接受）

## 安全

- 无新权限（工作区外 inbox 需插件写权限——与 design-review.log 同权限模型）
- 消息非指令（role:user 帧投递，收方自行判断，防跨会话指令注入）
- from 不可伪造（服务端取值）；to 分级校验防乱发；append-only 天然审计；归档不丢历史
